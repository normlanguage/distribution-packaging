Kryo provides fast and efficient serialization of Java objects.

I intend to package the primary, unshaded Kryo 5 artifact
(com.esotericsoftware:kryo) as libkryo5-java. This is needed for the
Norm toolchain packaging effort tracked in ITP #1147751.

Debian currently provides the older Kryo 2 API. The proposed package uses
/usr/share/java/kryo5.jar and the upstream Kryo 5 Maven coordinates,
so the existing Kryo 2 package can remain available for its consumers.
This does not relocate Java packages or promise both APIs can be used
in the same class loader.

A 5.6.2+ds source package excluding bundled JARs has been prepared using
maven-debian-helper and distribution-provided Java dependencies. It has
built successfully with sbuild in Debian unstable, including 304 Java
tests. An installed-package autopkgtest checks serialization round trips
and shared-reference identity. Upstream optional Kotlin tests are not run.

I would welcome coordination with the Debian Java team, packaging review
and an upload sponsor. I am open to adjusting the package naming or
maintenance arrangement to fit the team's conventions.
